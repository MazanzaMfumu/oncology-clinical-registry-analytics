# Dashboard Deployment Architecture

## 1. Purpose

This document explains how the oncology dashboard is executed
locally and deployed publicly.

The project uses two distinct operating modes:

1. a local analytical mode based on the SQLite database generated
   by the real data pipeline;
2. a public demonstration mode based entirely on synthetic data.

This separation allows the analytical workflow to remain
reproducible without publishing the original dataset or derived
individual-level records.

## 2. Local analytical mode

The local mode is used on the project owner's computer.

It relies on the complete data pipeline:

1. acquisition of the documented public oncology dataset;
2. storage of the original file in `data/raw`;
3. preparation and harmonization with Python;
4. data quality validation;
5. creation of the relational SQLite database;
6. visualization of the prepared information with Streamlit.

The local dashboard uses the following database:

```text
data/processed/oncology_registry.sqlite
```

The following files remain local and are excluded from GitHub:

```text
data/raw/
data/interim/
data/processed/
```

This means that the original CSV, the intermediate files,
the validated individual-level dataset and the SQLite database
are not publicly redistributed.

## 3. Public demonstration mode

The public Streamlit deployment does not download or redistribute
the original oncology dataset.

On Streamlit Community Cloud, the local SQLite database is absent
because it is excluded from GitHub.

When the application cannot find the local SQLite database, it
automatically activates the public demonstration mode.

In this mode, the application generates an entirely synthetic
cohort using:

```text
src/demo_data.py
```

The synthetic observations:

- do not represent real patients;
- do not reproduce original individual records;
- are generated entirely by the project code;
- use a fixed random seed for reproducibility;
- are used only to demonstrate filters, indicators, tables and charts;
- must not be interpreted as official clinical statistics.

## 4. Automatic mode selection

The application uses the following logic:

```text
SQLite database available
        ↓
Local analytical mode
        ↓
Dashboard based on the locally prepared dataset
```

If the database is unavailable:

```text
SQLite database unavailable
        ↓
Public synthetic demonstration mode
        ↓
Dashboard based on entirely synthetic data
```

The main application file is:

```text
app/streamlit_app.py
```

## 5. Data governance decision

The separation between local and public modes is a deliberate
data governance decision.

It prevents the publication of:

- the original Kaggle CSV;
- intermediate individual-level files;
- validated individual-level files;
- the locally generated SQLite database.

At the same time, it keeps the portfolio application publicly
accessible to recruiters and other reviewers.

The public dashboard is therefore a technical demonstration.
It is not:

- a hospital registry;
- an official source of cancer statistics;
- a diagnostic tool;
- a prognostic tool;
- a medical decision-support system.

## 6. Running the local analytical mode

Open a terminal at the root of the project and run the pipeline
in the following order:

```powershell
python -m src.prepare_data
python -m src.validate_data
python -m src.build_database
python -m streamlit run app/streamlit_app.py
```

The expected active source in the dashboard is:

```text
Source active: local SQLite database produced by the pipeline.
```

## 7. Testing the synthetic demonstration mode locally

The public mode can be tested from the local computer before
deployment.

In PowerShell, activate the synthetic mode:

```powershell
$env:USE_SYNTHETIC_DEMO="1"
```

Then launch the dashboard:

```powershell
python -m streamlit run app/streamlit_app.py
```

The expected active source is:

```text
Source active: synthetic data generated by the project code.
```

After completing the test, stop Streamlit with:

```text
Ctrl + C
```

Then remove the temporary environment variable:

```powershell
Remove-Item Env:USE_SYNTHETIC_DEMO
```

Confirm that the variable has been removed:

```powershell
Test-Path Env:USE_SYNTHETIC_DEMO
```

The expected result is:

```text
False
```

## 8. Public deployment

The public application is deployed from the GitHub repository
using Streamlit Community Cloud.

Deployment settings:

```text
Repository: doudoumazanza/oncology-clinical-registry-analytics
Branch: main
Main file path: app/streamlit_app.py
```

Because the SQLite database is not published on GitHub, the
deployed application automatically uses the synthetic
demonstration mode.

## 9. Interpretation limits

The public dashboard demonstrates:

- application structure;
- interactive filters;
- aggregated indicators;
- data quality visualization;
- Streamlit deployment;
- separation between analytical and public data environments.

The synthetic values must not be used for medical, clinical,
epidemiological or institutional decision-making.
